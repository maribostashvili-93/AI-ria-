# Roadmap

AI RIA is not an HTML analyzer. It is an **Agent Memory + Context Compression + Figma Intelligence platform** — the shared layer between AI agents and the repositories they work on.

The roadmap is organized into versions. Each version ships standalone value, and everything builds on the v0.1 core: Repository Intelligence feeds Compression and Memory; Handoff and Context Packs are outputs of Memory; everything later (Design, Security, Skills, Routing) plugs into the same core.

```
v0.1 ──────────► v0.2 ──────────► v0.3 ──────────► v0.4
CORE             Design           Security &       Autonomy &
Compression      Intelligence     Skills           Routing
Memory
Handoff
```

---

## v0.1 — CORE

The four capabilities that make AI RIA unique. Nothing else ships before these work.

### 1. Repository Intelligence (foundation)

A persistent, queryable understanding of any repository.

- Repository scanner: structure, modules, dependencies, entry points
- Convention detection: naming, file organization, code style, commit patterns
- Project map: compact, structured representation agents query instead of re-reading files
- Incremental updates as the repo changes; knowledge survives across sessions
- Exposed via open protocols (MCP first) — no per-agent adapters

**Done when:** an agent can ask "how is this project structured, and what are its conventions?" and get an accurate, token-cheap answer without scanning the repo itself.

### 2. Context Compression Engine

Not lossy summarization — **semantic compression**. A 500k-token repo becomes a ~15k-token structured pack that preserves what agents actually need:

```json
{
  "architecture": {},
  "active_files": [],
  "critical_components": [],
  "recent_changes": [],
  "design_rules": [],
  "security_rules": []
}
```

- `ria context` → generates `.ria/context-pack.md`, optimized for any agent
- `ria context cursor` / `ria context claude` → agent-specific packs
- Smart context selection: only what's relevant to the current task
- Deduplication: never pay twice for knowledge the layer already holds
- **Eval metrics from day one:** token savings per task, with task-quality checks — the 30–70% reduction claim must be measurable, not asserted

**Done when:** repository-aware tasks consume 30–70% fewer tokens with no measured loss in task quality.

### 3. Agent Memory Layer

What one agent learns, every agent knows. Claude refactors the navbar; RIA records:

```text
Decision: Navbar moved to shared layout
Reason:   Reduce duplication
```

Cursor opens the project next; RIA hands it:

```text
Previous decisions:
- Navbar moved to shared layout
- Tailwind is preferred
- Bootstrap is deprecated
```

- Decision log: what changed, why, by which agent
- Project rules: preferences, deprecations, constraints
- Warnings: known pitfalls ("do not edit payment.js")
- Session memory: long sessions distilled into dense summaries for continuity

**Done when:** an agent picks up a project cold and immediately knows the decisions, rules, and warnings accumulated by every previous agent session.

### 4. Agent Handoff Protocol

Handoff is not a separate system — `handoff.json` is a **task-scoped view of the Memory Layer**:

```
Memory Store (decisions, rules, warnings)
        │
        ├── ria context   → context-pack.md   (compression output)
        └── ria handoff   → handoff.json      (task-scoped memory view)
```

```json
{
  "task": "Improve checkout",
  "completed": ["header", "footer"],
  "remaining": ["cart"],
  "warnings": ["Do not edit payment.js"]
}
```

- `Claude → RIA → Cursor → RIA → Codex` with zero verbal re-explanation
- Open schema, vendor-neutral, versioned

**Done when:** an agent can stop mid-task and a different agent can resume it from `handoff.json` alone, without duplicate or conflicting work.

## v0.2 — Design Intelligence

### Figma Intelligence Layer

Not "extract colors" — a full **Design Memory** built from Figma:

```text
Figma → RIA → Design Memory
```

- Primary colors, spacing scale, typography, components, variants
- Output: a **Design Rules Pack** agents receive before generating any UI
- UI/UX consistency validation: generated UI checked against the design system, deviations flagged

### Design-to-Code Memory

Persistent mapping between design and implementation:

```text
Button ↕ button.tsx
Card   ↕ card.tsx
Navbar ↕ navbar.tsx
```

When a Figma component changes, RIA answers:

```text
Affected files:
- button.css
- button.js
```

**Done when:** UI generated by any connected agent uses the project's real design tokens and components by default, and a Figma change maps automatically to the affected code.

## v0.3 — Security Brain & Agent Skills Runtime

### Security Brain

- Security scanning of agent-generated changes: vulnerabilities, injection risks, unsafe patterns
- Secret detection: block credentials and keys from entering the codebase
- Dependency safety: flag risky or malicious packages agents try to add
- Policy engine: project-defined rules agents must respect
- Audit trail: what agents changed, what was flagged

### Agent Skills Runtime

Reusable, invokable skills on top of the core:

```bash
ria skill ui-review
ria skill compress
ria skill figma-review
ria skill security-review
```

**Done when:** every agent-generated change passes automated security validation, and skills run identically across connected agents.

---

## v0.4 — Auto UI Fix & Multi-Agent Routing

### Auto UI Fix

Design Memory + Security Brain combined: RIA detects design-system deviations and fixes them automatically, within policy limits.

### Multi-Agent Routing

- Shared state: all connected agents see the same project knowledge
- Task coordination: prevent duplicate or conflicting work
- Routing: send each task to the agent best suited for it
- Orchestration hooks: integrate with multi-agent frameworks

**Done when:** multiple agents work the same project simultaneously, coordinated through AI RIA, with handoffs that lose nothing.
